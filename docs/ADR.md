# Architecture decisions

These decisions record choices that would materially change the app if reversed. Coding rules
are in [AGENTS.md](../AGENTS.md); calculation assumptions are in [methodology.md](methodology.md).

| ID      | Date       | Status                | Decision                                                                                                                                                                                                           | Rationale and consequences                                                                                                                                                                                                                 |
| ------- | ---------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADR-001 | 2026-11-25 | Accepted; implemented | Build the site as static pre-rendered HTML with zero frontend framework and minimal progressive-enhancement JavaScript, backed by a GitHub Action that parses Ofgem's Annex 9 workbook into `data/price-cap.json`. | All data is static and updates quarterly. Pre-rendering HTML at build time removes runtime framework weight and network fetches (`connect-src 'none'`), giving near-instant load times and full core access even with JavaScript disabled. |
| ADR-002 | 2026-11-25 | Accepted; implemented | Use Temporal (`temporal-polyfill`) as the sole date and time model.                                                                                                                                                | Cap period boundaries follow UK civil calendar dates (`Europe/London`), so Temporal avoids host-timezone assumptions and JavaScript `Date` quirks.                                                                                         |
| ADR-003 | 2026-11-25 | Accepted; implemented | Use `decimal.js-light` for all numeric arithmetic throughout the app and parser tooling.                                                                                                                           | Binary floating-point rounding can shift pence per kWh and standing charge rates by 0.01p. Values stay as `Decimal` through calculations and round explicitly at display and serialisation boundaries.                                     |
